# Building blocks

Which OpenMinion building blocks Follow-Through uses, what worked, what did not, and the evidence.
Measured on the pinned version (openminion 0.1.23).

| Block | Where | Works | Gap | Evidence | Upstream |
|---|---|---|---|---|---|
| Memory records (`MemoryService`, SQLite store) | not used; `src/followthrough/ledger.py` instead | `upsert_record` keeps one live record per (scope, type, key) | no exact lookup by key; `list` returns records past `expires_at`; namespace ids reject `/` | `tests/test_memory_gap.py`, ADR 0007 | #677 (open; expiry part) |
| Scheduler (`openminion cron create/run/pause`) | `src/followthrough/schedule.py:116`, `:130`, `:144` | `cron create --cron "30 6 * * *" --tz UTC` stores the task with the right `next_due_at`; with the daemon up, `cron run` finishes in about 1 s | `cron run` only queues: without a running daemon the run stays `queued` and the CLI still reports `ok`; the CLI has no `cron delete` (pause is the closest); a finished run reports `cron_delivery_failed` ("FOREIGN KEY constraint failed") when the task has no delivery target | `tests/test_schedule.py`, `docs/TEST-RESULTS.md` Scheduling, ADR 0008 | not yet searched |
| Daemon (`openminion daemon start/stop`) | `src/followthrough/schedule.py:126`, `src/followthrough/omhome.py:116` | start/stop by pid file in the data root; stop leaves no process | default port 18789 is shared by every OpenMinion home on a host: a second home's `daemon start` finds another daemon on that port and fails ("endpoint identity does not match"); each home needs its own `runtime.ipc_port` | `docs/TEST-RESULTS.md` Scheduling, ADR 0008 | not yet searched |
| Diagnostics (`openminion doctor --check-turn --json`) | `src/followthrough/schedule.py:60` | JSON summary + per-check status; the turn check passes with the key-free echo provider | none found | `tests/test_schedule.py`, `docs/TEST-RESULTS.md` Diagnostics | n/a |
| Freshness classifier (runtime, before every turn) | `config/prompts.toml` `[publisher] message` | an explicit tool request ("Call post_comment …") skips the classifier; the tool is then called and the approval callback receives the exact arguments | a plain request whose payload contains dates is classified as needing live, dated evidence and the runtime answers it itself with 0 tool calls ("Missing exact-date evidence for an exact-date freshness answer"), so a dangerous tool never reaches approval | `docs/TEST-RESULTS.md` Sandbox approval demo, `tests/test_post.py::test_publisher_message_is_an_explicit_tool_request`, ADR 0009 | not yet searched |
| Parallel subagents (`subagent()` + `@tool`, one `APIRuntime`) | `src/followthrough/agents.py` `read_threads` | each subagent keeps its own session; one runtime per worker runs turns in parallel (8 threads in 94.5 s) | `Agent.run` holds the runtime's tool-registry lock for the whole turn when the agent has decorated tools, so subagents sharing one runtime run one at a time (8 threads in 305 s with 8 workers) | `tests/test_runtime_pool.py`, `docs/TEST-RESULTS.md` Live sweep, ADR 0010 | not yet searched |
| Provider `base_url` (built-in `anthropic` provider) | `src/followthrough/agents.py` `write_agents_json`, `src/followthrough/replay.py` | pointing `base_url` at a local endpoint sends every model call there, so a whole sweep can be recorded and replayed offline | requests are not stable across runs: the runtime adds turn/capture ids, remaining time, memory ids and the working folder to prompts, and cuts one section at a fixed length; the forced `tool_choice` of the freshness classifier is rejected by `claude-sonnet-5-5` (HTTP 400; the turn carries on) | `docs/TEST-RESULTS.md` Key-free demo, ADR 0012 | none filed |
